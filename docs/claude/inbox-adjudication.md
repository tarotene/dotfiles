# inbox-adjudication — 溜まった受信箱を、返信の裁定から処理する判断知識

スキル: `config/claude/skills/inbox-adjudication/SKILL.md`
事例: `config/claude/skills/inbox-adjudication/cases.md`

## 動機

溜まったメールの処理を頼まれ、既読化とアーカイブを中心にした計画を出したところ、
「返信が必要なものを片っ端から裁定したい」と却下された。既読化から始めると、返信すべき
相手と期限のあるものが埋もれたまま処理済みになる。

## 器をスキルにした理由

- 発動の場面を「メールを処理して」「未読を整理」といった言葉で言い切れる。
- 手順は判断を含み、機械で強制できる部分は無い(送信や削除をしない約束は、権限と
  外部発信の方針で別に守られている)。
- 数字や固有の運用(差出人の一覧、媒体の台帳)はスキルに入れない。それらは
  private なリポジトリ側の正本にある。

## 内部構成の意図

本文は不変の順序と原則(読む、裁定に出す、反映する、フィルタにする、最後に整える)。
増え続ける実話は `cases.md` に分ける。

## 日次モード

毎朝の処理は `daily-desk`(`docs/claude/daily-desk.md`)のメールの段から呼ばれる。件数が少ないので、
一括処理の HTML ページはやめ、Gmail で返せるスレッドは返信形式の Gmail の下書きにする。HTML のページは
Gmail の外の媒体の分だけ。フィルタの追加と既読化は、日次モードでは行わない。フィルタの見直しは
フィルタ定義を持つリポジトリの週次の見直しが担い、この手順の手順 5 と重なる部分は、そちらを正本にする。

## 運用

新しい失敗や、うまくいった手順が出たら `cases.md` に抽象化して追記する。順序が変わるときだけ
本文を直す。
