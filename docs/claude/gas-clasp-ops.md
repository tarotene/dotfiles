# gas-clasp-ops — Google Apps Script を clasp で CLI 操作する

`config/claude/skills/gas-clasp-ops/SKILL.md` の設計根拠。
ADR-0030(GAS/clasp 基盤の配置)の実装に対応する。

## なぜこれが必要か

Google Apps Script (GAS) は既定では script.google.com への手動コピペ実行が
前提で、実行結果(生成した Form/Spreadsheet の URL など)はブラウザの実行
ログにしか出ない。ログを閉じると結果を拾い直せず、スクリプトの再実行が
必要になる、という実際の不便が発生した(ある GAS スクリプトが Google Form
を生成して URL を `Logger.log` だけに出していたケース)。また Drive 上に
オブジェクトを作成する呼び出し(`FormApp.create` 等)を冪等化せずに置いて
おくと、再実行のたびに Drive 上のオブジェクトが増える二次被害もある。

Google Docs / Spreadsheet 系の自動化は他の GAS プロジェクトでも今後繰り返し
発生しうるため、単発の回避策(実行ログを見落とさないよう注意する、等)では
なく、GAS を CLI から操作できる基盤を整備する方が長期的に安い。

## なぜスキルにしたか

「clasp をどう使うか」(初回セットアップの手順・ログインの作法・スクリプト
側で守るべき規約)は機械的に強制できるものではなく、次に GAS プロジェクトを
触るときに思い出す必要がある判断知識。フックで強制する性質のものはない
(実行結果の取りこぼしはコードレビュー・実機確認で防ぐもので、パターン
マッチで機械検査できる違反ではない)ため、器はスキル一本とし、専用の gate は
作らない。

## 内部構成の意図

- **正本は各利用リポジトリに分散**させ、dotfiles には「ツール(clasp
  バイナリ)」と「運用ナレッジ(スキル)」だけを持つ。GAS 専用の集約
  monorepo は作らない判断の理由は ADR-0030 を参照。
- SKILL.md は「初回セットアップ → ログイン → 日常操作 → スクリプト側の規約 →
  複数プロジェクトの扱い」の順に並べ、初見でも上から実行すれば動く手順書
  として機能させる(判断が必要な箇所だけ理由を添える)。
- 秘密(`client_secret.json` / `.clasprc.json`)の置き場所はホストローカルに
  固定し、home-manager 管理外・git 管理外と明記する。ADR-0010(sops
  ランタイム復号チャネルの退役)の「新しいシークレットはチャネルを都度選ぶ」
  という原則に従った選択であり、ADR-0022(esa トークン)とは異なり GPG 暗号化
  はしない(clasp 自体が復号ラッパーを挟める構造ではないため)。

## 運用(いつ・どう追記するか)

- clasp の破壊的変更(メジャーバージョンアップ等)に追従するときは、
  SKILL.md の該当手順を書き換える。バージョン固定はしていないので
  (`home/modules/packages.nix` の nixpkgs pin に追従)、`clasp run-function`
  等のコマンド名が変わった場合はここが唯一の更新箇所になる。
- 新しい GAS プロジェクトを立ち上げて分かった知見(スコープ不足で刺さった
  エラーメッセージのパターンなど)は、事例として SKILL.md に追記するか、
  肥大化するようなら `cases.md` に分離する(skill-gardening のサニタイズ
  規則に従い、固有名詞・URL・実データは含めない)。
