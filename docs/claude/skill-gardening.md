# skill-gardening スキル

`config/claude/skills/skill-gardening/SKILL.md` — 作業セッションで得た知見をこの公開リポジトリに固定化するときに発動する、スキルを育てるためのメタスキル。

## 動機

`diagramming` スキルを新設する際、以下の判断を都度検討し直す必要があった:

- この知見はスキル・フック・CLAUDE.mdのどれに落とすべきか
- dotfiles側の配線(ファイル配置→`home/modules/claude.nix`への追加→設計ドキュメント→switch→動作確認)の手順
- 公開リポジトリに書く以上、社内固有の情報(社名・製品名・URL等)をどう除去するか

これらは今後別の知見を貯めたくなったときにも毎回再発する判断であり、一度メタスキルとして書いておけば同じ検討を繰り返さずに済む。

## サニタイズ規則の正本をここに置く理由

サニタイズすべき対象(固有名詞・URL・実物データ等)は知見の内容に関係なく共通のチェックリストである。各スキルの`cases.md`にこの規則を書くと、スキルが増えるたびに同じ内容が複製され、規則を更新するときに全ファイルを直す必要が出る。`skill-gardening`側に正本を置き、各スキルの事例集からは「追記時は`skill-gardening`を参照」と1行で指すだけにすることで、重複を避けている。

## 棚卸しをスコープ外とした理由

既存スキルの肥大・重複・陳腐化を定期的に点検する「棚卸し」機能も検討したが、発動契機が「知見をスキル化したい」という単発のイベントとは異なり、定期実行(例: `/loop`)向けの機能である。同じスキルの`description`に単発イベントと定期タスクの両方のキーワードを持たせると発動精度が落ちるため、必要になった時点で別スキルとして切り出す方針にした。
