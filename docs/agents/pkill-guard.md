# pkill-guard — 検索語が自分のコマンド行に当たる `pkill -f` / `pgrep -f` を、実行前に止める

実装: `crates/pkill-guard`(Rust)。`hook-router` の規則として走る(`crates/hook-router/src/rules.rs`、
`tools: Bash`)。エージェントの種類は問わない(`test-output-guard` と同じく、`Bash` のコマンド文字列だけを見る)。
Issue: No-Issue(wrap-up の気づき「`pkill -f` で、検索語が自分の Bash コマンド行にも含まれて自分のシェルを殺した
(exit 144、143)。同じ誤りを 2 回した」。文章の規範は無く、検査も無かった)

## 動機

`pkill -f 'パターン'` は、プロセスのコマンド行全体からパターン(正規表現)を探して止める。エージェントが打った
Bash のコマンド文字列は、実行するシェル自身のコマンド行(`bash -c '<コマンド>'`)にそのまま入る。したがって、
パターンが自分の文字列に当たる形(`pkill -f trial.sh`)は、自分のシェルを探し当てて止める。呼び出しは終了コード
143(SIGTERM)や 144 で落ち、後ろのコマンドは実行されない。2026-10-31 に `pkill -f trial.sh` と
`pkill -f tC/cl2/db` で、同じセッションの中で 2 回起きた。

`pgrep -f` は止めないが、自分のシェルの行にだけ当たって「動いている」と誤判定する(2026-10-28、`pgrep -f obsidian`
が自分のシェルの行だけに当たり、ホストの Obsidian が見えず「動いていない」と読みかけた。sandbox の PID namespace の
別の理由と重なっていた)。

同じ型(文章の規範はあったが破られた、または規範が無かった)に `test-output-guard`(`docs/agents/test-output-guard.md`)、
`sandbox-compound-guard`(`docs/agents/sandbox-compound-guard.md`)がある。そこで入れた「トークン単位で見て、
実行前に deny して案内する」検査と同じ形を使う。

## 判定

コマンド文字列をトークン化し、区切り(`;`・`&&`・`||`・`|`)ごとの「コマンド」に分ける。コマンド位置(先頭の
`VAR=value`・`env`・予約語を読み飛ばした先)が `pkill` か `pgrep`(パスが付いても同じ)で、次を**すべて**満たすとき deny する。

1. `-f` / `--full` がある(束ね書き `-fi` でもよい。`-9`・`-TERM` のシグナルは読み飛ばす)。
2. `-x` / `--exact`(完全一致)が**無い**。完全一致は、コマンド行全体が検索語に一致する必要があり、シェルの長い
   コマンド行には当たらない。
3. 検索語(最初の位置引数。`-u USER`・`--signal TERM` などの値は読み飛ばす)を正規表現として読み、**検索語そのものの
   文字列に当たる**(`-i` があれば大文字小文字を無視する)。検索語はコマンド文字列にそのまま現れるので、これが
   自分のコマンド行に当たる条件になる。

### 通す形

- **括弧の技**: 検索語の 1 文字を `[]` で囲む(`pkill -f '[t]rial.sh'`)。正規表現としては `trial.sh` に当たるが、
  文字列 `[t]rial.sh` には当たらない。拒否の文は、検索語の最初の英数字を囲んだ形を示す。
- `-f` が無い(プロセス名で探す: `pkill foo`)、`-x` がある、検索語が `^` で始まるなど自分の文字列に当たらない形、
  変数の展開(`"$PATTERN"`。中身は分からない)。
- クォートの中の文言(`echo "pkill -f foo"`、コミットメッセージ)。トークン単位なので当たらない。heredoc の本文は見ない。
- 正規表現として読めない検索語、トークン化できないコマンド: 判定不能として通す(fail-open)。

`bash -c '…'` の中身は再帰して見る(深さ 2 まで)。

## 逃げ道

コマンドに `PKILL_GUARD_ALLOW=1` の語を足す(環境変数でも同じ)。コマンドに残るので、あとから読める。

## 軸と限界

軸は「検出のみ」: 拒否文で書き換えを案内するが、自分に当たる `pkill -f` を書くこと自体は表現できる。

- `sudo pkill -f …`・`xargs pkill -f …`・`nohup pkill -f …` のように、別のコマンドが包む形は見ない(コマンド位置が
  `pkill` でない)。
- 検索語が自分のコマンド行に当たらなくても、別のプロセス(同じ名前の他のプロセス)を止める危険は、この検査の範囲外。
- POSIX の拡張正規表現(`pkill` の実装)と Rust の `regex` の方言の差は、`[]` を使う単純な語では出ない。差が出る
  複雑な検索語は、読み違えて通す側に倒れうる。

## 先行例

- `crates/test-output-guard`(同じ型の PreToolUse の deny と逃げ道)。
- 括弧の技は、`ps aux | grep '[f]oo'`(grep 自身の行に当たらない書き方)として古くから知られる。ここでは一次の文献を
  取得していない。
