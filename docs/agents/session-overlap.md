# 同じ議題を別のセッションと重ねない: 確かめる手段の実測

共有 AGENTS.md「同じ議題を、別のセッションと重ねて議論しない」の根拠(#1263)。2026-10-30 に、同じ議題
(物品の調達先と納期の調べ物)を 2 つの Claude セッションが並行して扱い、本人が同じ質問に 2 回答え、
ブラウザのプロファイルを取り合って起動に失敗した。

## 実測した手段(2026-11-05、arcturus、Claude Code)

| 手段 | 読めたもの | 議題は読めるか |
|---|---|---|
| `ListAgents`(Claude Code のツール) | 自分のサブエージェントの一覧(種類・状態・経過時間)と、他のセッションの一覧(セッション名・対話型か・待機中か作業中か・開始からの時間) | 読めない。セッション名がそのセッションの題の代わりになる |
| `herdr workspace list` | 全 workspace のラベル・チェックアウトの場所(リポジトリと worktree)・エージェントの状態・open Issue 数 | 読めない。worktree のラベルとリポジトリが手がかり |
| `~/.local/state/claude/wrapup/*.jsonl` | リポジトリごとの、wrap-up の気づきの行(題名と詳細)と、起票済みの退避(`.filed.jsonl`) | 読めない。今日の議題ではなく、セッションの終わりに溜まる気づき |

`herdr workspace list` は、サンドボックスの外でないと実行できない(サンドボックスの中では
`Operation not permitted`)。

## 使い方

- 新しい議題を始めるときに、`ListAgents` を 1 回読む。他のセッションのセッション名が、これから扱う議題に
  近いとき(例: 同じリポジトリ名・同じ作業名)は、`herdr workspace list` で、そのセッションの worktree が
  同じリポジトリか、状態が作業中かを読む。
- 名前だけでは重なりを判定できない。判定できないときに黙って片方を選ばず、重なりを疑うなら本人に 1 回
  だけ聞く(共有 AGENTS.md の規約)。疑わないなら、自分の作業を進める。
- 手を引く側は、その議題の書き込み(予定・PR・Issue・共有のブラウザのプロファイル)に触れない。

## 限界

- 議題そのものを機械的に比べる手段は、この 3 つのどれにも無い。セッションが自分の議題を宣言する場所
  (herdr の workspace のラベルやメタデータ)を足す案は、必要になったときに別の Issue にする
  (`herdr-sidebar-metadata.md` が先行例)。
