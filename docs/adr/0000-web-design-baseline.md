# ADR-0000 — Pages のデザインは、DADS を土台にした自分用の基準に従い、正本は公開のこのリポジトリに置き、第三者からの書体・スタイルの読み込みを禁じる

- Status: Accepted
- Date: 2026-11-23
- Issue: No-Issue(本人が保守する Web の面の見た目に、横断の基準が無いことの裁定。非公開のリポジトリの追跡で、問いごとに本人が答えて決めた。この ADR は、その結果のうち公開してよい規則だけを残す)

## Context

本人が保守する Web の面(GitHub Pages・Cloudflare Workers のサイト・claude.ai の Artifact の雛形)は、2026-11-22 の読み取りで、次の状態だった。

- 生成器は 8 種類以上。見た目を共有するファイルは 1 つも無く、配信(`deploy-worker`、ADR-1553)とビルド(`docs-python`、ADR-640)だけを共有している。
- 色のトークンの語彙が少なくとも 5 系統、書体の組が少なくとも 12、暗色の仕組みが 4 通り以上。同じ CSS を手で複写した組が少なくとも 5 つあり、すでにずれている。
- 同じ意味の色が面で食い違う(誤りと注意を同じ色で描く面と、赤と黄土に分ける面)。和文の書体を指定していない面がある。
- 見た目の値を裁定した記録は、1 つのダッシュボードの配色(個人の記録のリポジトリの ADR)に限られ、横断の規約は無かった。規約をどのリポジトリが持つかの裁定も無かった。

ADR-1660 の D6 は、アプリの骨子を「共有の部品にはしない。2 つ目の app が出たら裁定する」と保留している。その条件は、画面を持つ面が複数になったので成立している。

2026-11-23 に、次の一次ソースを読んだ(いずれも取得 2026-11-23)。

- デジタル庁, ローカルデザインシステム(スタイルガイド)(2026-10-14 更新) https://design.digital.go.jp/dads/guidance/local-design-system/ 。「固有の組織に依拠したブランド概念を備えていないため、使用にあたってはローカルデザインシステムの作成が前提となります。」「初期値として設定されたデザイントークンは、特定の外観を規定するものではなく、編集の起点として位置づけています。」「決めたルールに基づき、キーカラーをブランドカラーに置き換えます。」「セマンティックカラーの色相と意味の結びつきは変更しない。」
- デジタル庁, 利用上の注意事項(2026-11-18 更新) https://design.digital.go.jp/dads/introduction/notices/ 。「なお、編集・加工した情報を、あたかもデジタル庁が作成したかのような態様で公表・利用してはいけません。」(出典の記載と加工の記載を求める本体の条文)。コードスニペットの節は、加工して作った画面の部品について、出典を明記する必要はないと書く。2026-11-18 の改訂は、更新履歴によれば、アイコン素材(Material Symbols)の追記 2 点。**改訂前の本文は取得しておらず、差分そのものは未確認。** 注意事項はデザイントークンを名指ししていない。トークンの配布元(`digital-go-jp/design-tokens`)は MIT ライセンスで、CSS の変数ファイルを配る。トークンをコードスニペットと同じ扱いと読むのは推論である。
- Simple.css(https://github.com/kevquirk/simple.css)の `simple.css` 全文と、new.css(https://github.com/xz/new.css)の `new.css` 全文と README。どちらも、クラスなしで素の HTML 要素に見た目を付ける CSS で、MIT、archived でない。層(部品・ページの型)も、和文の書体指定も、合格条件(コントラストの検査)も、状態の色(成功・誤り・注意)の変数も持たない。new.css は、暗色のボタン文字の変数名が `--nc--dlk-tx` と綴り違いで、暗色ではその色が未定義になる。
- このリポジトリの HTML・CSS で、第三者から書体・スタイルを読むのは、裁定ページの `template.html` の 1 つだけ(Google Fonts の `<link>` 3 行)。

## Decision

### D1: 基準は、既製の 1 システムでなく、DADS を土台にした自分用のデザインシステムとする

層は GOV.UK Design System の 3 層(Styles・Components・Patterns)、合格条件は WCAG 2.2 AA(文字 4.5:1、図形 3:1、押す領域 24×24 CSS px)、和文の組版は JLReq と CSS Text に置く。値(文字の大きさ・行間・余白・角丸・状態の色)は DADS のトークンを起点にし、変えた値だけ理由を書く。DADS が持たない部分(数式・図・印刷・既製テーマへの差し込み・面ごとの主色)だけを、自分の差分として正本に持つ。

本命: なし — 調べた範囲で、和文の値(本文 16px 以上・行高 1.5 以上・Noto Sans JP)と状態の色の意味と合格条件を最初から持つ候補が DADS だけだった。結論から出発したのでなく、候補を調べて残った。
対抗馬: 基準を持たず、WCAG と JLReq の数値条件だけを検査する案(同じ評価軸「値の根拠を、外部の一次情報に置くか、自分で書き続けるか」。依存は増えないが、値ごとの根拠を自分で保つ)。Simple.css(同じ評価軸。上の Context のとおり、全文を読んで、層・和文・合格条件・状態の色の変数が無いことを確かめた)。
外した候補: Pico CSS(2026-10-04 にアーカイブ済み)、material-tokens(2024-10-17 にアーカイブ済み)、Material Design 3・Primer・USWDS(和文の組版値を持たない)、new.css(上の綴り違い)。Simple.css と new.css は全文を読んだうえで、分析で外した。
既存手段: crates/repo-structure-check/src/web_assets.rs — 採用: DADS のデザイントークン(https://github.com/digital-go-jp/design-tokens、MIT)を値の起点にする。トークン本体の取り込みはこの ADR の範囲外で、この ADR は基準を宣言するだけである。
先行例: 上の Context の DADS の 2 ページ(取得 2026-11-23)と、UK Government Digital Service, GOV.UK Design System https://design-system.service.gov.uk/patterns/ (取得 2026-11-22。以前の読み取りの出典で、今回は再読していない)
差分: 一致 — DADS 自身が、ローカルデザインシステムの作成を前提とし、初期値を編集の起点とし、キーカラーを置き換えると書く。骨格は共通で主色は面ごと、という D4 と同じ形である。DADS の中で変えないのは、セマンティックカラーの色相と意味の結びつきだけ。
軸: 還元 — 値と合格条件を一から自分で書き続ける仕事を、DADS の一次情報で担わせる。

DADS の利用条件は、読んだ範囲では、加工して使うことを妨げない。守るのは次の 2 点である: 加工した情報を、デジタル庁が作成したかのような態様で公表・利用しない。デジタル庁のロゴを使わない(キーカラーとロゴは、自分の差分で置き換える。これは推論)。トークンのファイルを実質そのまま再配布するときは、MIT の著作権表示と許諾文を残す(MIT の一般条件からの推論で、`LICENSE` は冒頭だけを読んだ)。

### D2: 基準・トークン・部品の正本は、公開のこのリポジトリに置く

置くのは規則と共通の値だけで、個人の好みが出る主色は各面のリポジトリに残す。

先行例: ADR-0034(依存の向きは非公開から公開への 1 本だけ。「規則・スキーマ・導出手順は public、それを実例化した具体値は private」)(取得 2026-11-23)。個人の記録のリポジトリの裁定ページの形式の ADR D1(形式の正本を公開のこのリポジトリに置き、非公開側が pin する)(取得 2026-11-23)
差分: 一致 — 境界の線を同じ位置に引く。基準の対象に公開のページがあり、非公開のリポジトリは公開ビルドから読めない。ADR-1660 D6 の保留の条件が成立したので、「共有の部品にするか」は、この ADR で「する(正本はこのリポジトリ)」と裁定する。**配り方**(トークンを CSS で配るか JSON で配るか、各面のビルドへの取り込み方)は、実機での描画の実測の後に別の ADR で裁定する。
軸: 表現不可能 — 単一正本 > 複写+同期。規則の正本が公開側に 1 つあれば、非公開の面と公開の面が別々に同じ値を複写しない。

### D3: 対象の面を、「必須」「採用してよい」「対象外」の閉じた 3 区分で宣言する

- **必須**(従わない面は、理由つきの例外として記録する): 本人が保守する現役の Web の面(公開・非公開とも)、claude.ai の Artifact の雛形、雛形を持たず、その場で組む Artifact(エージェント向けの手順書を 1 本置き、正本のトークンと型を使わせる)。
- **採用してよい**(強制しない): 団体が持つ面。印刷物(色と書体の値だけを同じ正本から読めるようにし、組版は別にする)。
- **対象外**: アーカイブ済みの面。閲覧制限が効いているかを確かめるだけのページ。道具の既定の見た目のまま出す API ドキュメント。外部のサービスが表示する画面(Cloudflare Access のログイン画面)。

先行例: `docs/agents/personal-web-app.md`(18 行目。Artifact を標準の対象外とする)(取得 2026-11-23)
差分: 異なる — personal-web-app は、Artifact を、置き場が別でリポジトリの CI・配信と一続きにならないので対象外にした。見た目の基準は CI・配信でなく見た目の話なので、Artifact も必須に含める。personal-web-app の対象外の宣言は変えない。
軸: 表現不可能 — 閉語彙 > 自由記述+事後 lint。面の扱いを 3 語のどれかで宣言させ、扱いが宣言されない面を作れなくする。

### D4: 骨格は共通にし、主色と地の色合いは面ごとのテーマとして宣言する。状態の色(成功・誤り・注意)の意味は変えない

骨格は、役割の名前・尺度(文字の大きさ・余白・角丸・本文幅)・状態の色の意味・書体・合格条件。テーマは、役割名に値を与えて差し替える。

先行例: 個人の記録のリポジトリの公演ダッシュボードの ADR D3(公演期ごとのテーマを宣言して差し替え、状態の色はテーマの外で固定し、DTCG は採らない)(取得 2026-11-23)。デジタル庁, ローカルデザインシステム(上の Context の引用)(取得 2026-11-23)
差分: 一致 — 1 つのダッシュボードで採った型を、全面の規則に広げる。
軸: 表現不可能 — 宣言 > 手続き。テーマが差し替えるのは役割名の値だけで、役割の集合と状態の色の意味は固定される。

### D5: 最初に起こすページの型は 3 つ。学習・演習、裁定フォーム、ダッシュボード

どれも、本人が良い事例に挙げた既存の実物から要件を起こす。要件は、出力した HTML を機械で検査できる文にする(「1 画面に 1 つの判断」「主操作は 1 つ」「状態を色だけで伝えない」など)。学習・演習の要件(解答の前に答えさせる、各問に正誤を返す)は、学習科学の文献からの**推論**であり、出典の文そのものではない。要件の起こしと検査の実装は、この ADR の範囲外(次の ADR 以降)。既製テーマで出している面には、型を当てない。ページの構造はテーマが持っているので、テーマが公式に用意する差し込み口(追加 CSS・変数の上書き)から、共通の色の役割・書体・尺度だけを入れる。テーマ自体は書き換えない。

先行例: UK Government Digital Service, GOV.UK Design System の Patterns と Question pages https://design-system.service.gov.uk/patterns/question-pages/ (取得 2026-11-22。以前の読み取りの出典で、今回は再読していない)。ADR-1660 D4(検査できる型として宣言する)(取得 2026-11-23)
差分: 異なる — GOV.UK の型は利用者調査を前提にする。ここは、本人が良い事例として挙げた 3 つの実物から要件を起こす。
軸: 検出のみ — 型の要件は、出力した HTML を検査するだけで、要件を満たさないページを作れなくはしない。

### D6: 書体は機体の書体を既定とし、Noto Sans JP を先頭近くに置く。第三者からの書体・スタイルの読み込みは全面で禁止する

Web フォントは、自分のサイトから配信できる面(CSP を開けられるもの)に限り、その面のテーマの選択とする。禁止するのは、Google Fonts のような第三者の配信元からの書体・スタイルの読み込みである。表示のたびに第三者へ要求が飛ばず、CSP を閉じた面と同じ規則で、全面を統一できる。書体スタックの正本(先頭の並び)は、トークンの正本を置くときに確定する。

先行例: デジタル庁, タイポグラフィ https://design.digital.go.jp/dads/foundations/typography/ (取得 2026-11-22。以前の読み取りの出典で、今回は再読していない。本文 16px 以上、行高 1.5 以上、書体は Noto Sans JP で、機体の書体の使用も制限しないと読んだ)。dotfiles#1664 の提案 2(「`font-src` を開けず、機体に入っているものだけを使う」)(取得 2026-11-23)
差分: 一致 — DADS が機体の書体を制限しないことと、CSP を閉じた面の実績に沿う。先行例の面だけの規則を、全面に広げる。
軸: 表現不可能 — 外部読み込みを持たない形にすれば、開くたびに第三者へ要求が飛ぶ状態そのものが表現できない。

### D7: D6 の禁止は、新しい道具を作らず、既存の `repo-structure-check` に `web_assets` の検査として足す

このリポジトリの `*.html`・`*.htm`・`*.css` が、第三者の書体の配信元(`fonts.googleapis.com`・`fonts.gstatic.com`)、外部を読む `<link rel>`(`stylesheet`・`preconnect`・`dns-prefetch`・`preload`)、外部への `@import`、外部の `url(...)` を持つ `@font-face` を持たないことを、`cargo test` で検査する。例外の一覧は持たない。

本命: なし — 構造の不変条件を `cargo test` で検査する型が既にあり、その crate に足すのが最短だった。調査の前から決まっていたわけではない。
対抗馬: 専用の新しい crate(同じ評価軸「検査の置き場を、責務のちがう既存の crate に足すか分けるか」。`docs/agents/repo-structure-check.md` は、検査が 3 つ以上になるので 1 つの crate に集めると決めている)。HTML・CSS の lint を JavaScript の道具(stylelint・htmlhint)で足す案(同じ評価軸。新しい依存と実行環境が増える)。
外した候補: stylelint・htmlhint — 感触で外した(JavaScript の依存を、このリポジトリの CI に足すのが気になった)。分析ではない。
既存手段: crates/repo-structure-check/src/web_assets.rs — 拡張: crates/repo-structure-check(`manifest`・`hook_io`・`escape`・`host_names` と同じ型の `check_tree`)。
先行例: `docs/agents/repo-structure-check.md`(「構造の不変条件を `cargo test` で検査する型は、すでに 2 つある…検査が 3 つ以上になるので…1 つの crate に集める」)(取得 2026-11-23)
差分: 一致 — 同じ crate に、同じ型の検査を足す。例外の一覧を持たない点も、同文書の「違反を先送りする一覧には使わない」に従う。
軸: 検出のみ — 他のリポジトリの面は、この検査が走る範囲の外にある。ここは、このリポジトリが持つ HTML・CSS の文字列の形を検出するだけで、他のリポジトリの検査への配り方は、別の ADR で裁定する。

### D8: 裁定ページの `template.html` から Google Fonts の読み込みを外し、書体を機体のスタックに替える

D6 を、このリポジトリで唯一の違反だった面に適用する。`<link>` の 3 行を削除し、`--font-body` を `"Noto Sans JP", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic", system-ui, sans-serif`、`--font-mono` を `ui-monospace, "SFMono-Regular", Menlo, "Noto Sans Mono", monospace` にする。この並びは、D6 に合わせた暫定の形で、正本の確定は別の ADR で行う。

先行例: ADR-1660(単一正本を表現不可能の軸で採る型)と、`config/agents/skills/inbox-adjudication/reference/verdict-page/FORMAT.md`(「形を変えたら `format_version` を上げる」の「形」は、入力のデータと保存先の文書の形)(取得 2026-11-23)
差分: 一致 — 変えるのは CSS の書体の指定と `<link>` だけで、入力の形・保存先の形・差し込み点(`__DATA__`・`__OPTIONS__`・`__FORMAT_VERSION__`)は変えない。よって `format_version` は上げない。
軸: 表現不可能 — D6 と同じ。外部読み込みの無い形にするので、違反が検査より前に存在しない。

## Alternatives considered

D1 の対抗馬・外した候補、D7 の対抗馬・外した候補を参照。D4 では、値まで全面で同一にする案(主色も 1 組に決める)と、合格条件の数値検査だけを共通にする案を、本人が退けた。前者は、面ごとの個性を持たせた既存の裁定(公演ごとの配色)と、良い事例に挙げた面の色の意味づけを、例外か作り直しにする。後者は、役割の名前・尺度・状態の色の意味が面ごとに別である問題を残す。

## Consequences

- 配り方(トークンを CSS で配るか JSON で配るか、各面のビルドに取り込む手段)、トークンの正本、部品、ページの型の起こし、各面を正本に従わせる作業は、この ADR の範囲外で、実機での描画の実測の後に別の ADR で裁定する。読んだ範囲の事実は次のとおり(取得 2026-11-23): 各面の CI は `actions/checkout` に `submodules:` を指定していない。このリポジトリの共有 action(`deploy-worker`・`docs-*`)は自分では checkout しない。Typst は `json(`・`toml(`・`yaml(` でデータを読めるが、色・書体をデータから読む既存の例は無い。公開の団体サイトは Actions の自前ビルド(Jekyll 4.4 + Dart Sass)である。
- dotfiles#1664(personal-web-app の標準に、画面の作り方を足す提案)は、この裁定を受けて中身を決める。D6 は、その提案 2(フォント)と同じ向きで、1 の CSP と 3 の狭い画面の表は、この ADR の範囲外である。
- 検査の範囲はこのリポジトリの内側だけで、他のリポジトリの面は、この検査では守られない。他のリポジトリへの配り方が決まるまで、D6 の禁止は、それらの面では文書の規則にとどまる。
- 裁定ページの再公開(次の一括処理)から、書体は機体のものになる。Zen Kaku Gothic New と IBM Plex Mono を持たない機体では、見え方が変わる。
