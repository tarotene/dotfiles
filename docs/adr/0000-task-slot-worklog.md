# ADR-0000 — 作業の枠の状態を worklog の slot kind で追い、時間枠は行に持つ

- Status: Accepted
- Date: 2026-10-30
- Issue: #1290
- Amends: ADR-998(`worklog` の kind の閉語彙を 7 つから 8 つにする。D1〜D5 の他の決定は変更しない)

## Context

自分一人でやる作業の枠(出向く予定ではないもの。時間枠つき)の状態は、予定データ(Git の TOML)にあり、
作る・済んだ・組み直す・やめる、のたびに PR を強いている。この粒度は Git に置くには重い。ADR-998 は、
粒度の小さい記録を vault の当日ノートに置くと決めた。

`worklog` は、未裁定のメール項目を `mail` 行の畳み込みで追っている(ADR-1259)。書き込み口(日次ノートの
解決・flock・読み戻しの検査)、語彙 JSON を `include_str!` で読んで許されない遷移を書かずに止める作り、
`open` / `check` の読み出しが既にある。作業の枠は、メールと違って外から読み直す受信が無く、時間で
自動的に再通知も失効もしない。本人が「済んだ」「やめた」「組み直す」と裁くまで、枠は未了のまま残る。

## Decision

### D1: 作業の枠の状態を、`slot` kind の行を出来事として畳み込んで決める

新しい台帳は作らない。`worklog` の kind に `slot` を足し(kind は 8 つ)、同じ鍵の行を日付・時刻・ノート内の
順にたどって状態を決める。状態は `scheduled`(未了)、`done`・`dropped`(終端)。出来事は `plan`
(新規 → scheduled。agent)、`resched`(scheduled → scheduled。person。時間枠を書き換える自己遷移)、
`done`・`drop`(scheduled → 終端。person)。済んだかどうかは本人にしか分からないので、`done`・`drop`・
`resched` の行為者は person で、エージェントは本人の裁定を受けて書く。終端の後の出来事は、書かれず、
読むときは食い違いとして数える。

軸: 還元 — 書き込み口が既にある仕事のために、同じ仕事をする口と置き場を増やさない。

### D2: kind の名前は `slot` にする

`worklog` には、Gmail の外で片付けた人手の作業を自由記述で書く `task` kind が既にある。`task` に文法を課すと、
既存の `[task]` 行が解析できない行になる。作業の枠の kind は `slot` とし、CLI は `worklog add slot …`・
`worklog slot open|overdue|check` にする。語彙のディレクトリ名 `task-slot` は、対象の名前として保つ。

軸: 表現不可能 — 自由記述の行と文法つきの行を、同じ kind に混ぜない。

### D3: 時間枠と参照 Issue は行に持ち、鍵は枠の id にする

鍵は kebab-case の短い id(例 `reader-bot-resume`、64 文字まで)。`plan` と `resched` の行は `start:` と
`end:` を ISO 8601(`YYYY-MM-DDTHH:MM[:SS]` にオフセット `Z` か `±HH:MM`)で持ち、`end` は `start`
より後でなければ書けない。オフセットの無い時刻は、どの瞬間か決まらないので受けない。`plan` の行だけが
`issue:OWNER/REPO#N` を複数持てる。本文・要旨・個人名を持つ欄は無い。書き込み口は本文を正規の形
(`start`・`end`・`issue` の順)にそろえ、同じ内容は同じ行になる。

`mail` の鍵は外から届く受信で、読み直しが同じ鍵になることが冪等性の根拠だった。枠の鍵は自分が決める id
なので、同じ鍵は二度 `plan` できず、終端に入った後も使い回せない。同じ内容の `plan` の再実行(最初の `plan`
と同じ本文)だけは記録済みにする。時間枠を変えるのは `resched` である。

軸: 表現不可能 — 終了が開始より前の枠、オフセットの無い時刻、使い回された鍵を書けなくする。

### D4: 語彙は `mail` と別の JSON にし、タイマーを持たない。「過ぎた」は導く値にする

`config/agents/task-slot/vocabulary.json` に状態 3 つと出来事 4 つを置く。形は `mail-lifecycle` の語彙と
同じ(`states`・`events`)で、`timers` だけが無い。再通知も失効もしないので、機械が書く出来事(`mail sweep`
に当たるもの)は置けない(語彙の読み込みが `machine` を拒否する)。`worklog slot overdue` は、未了のうち
終了時刻が今より前の枠を、終了の古い順(同じなら鍵の順)に出す。`overdue` は状態ではない: 状態として保存
すると、時刻と状態が食い違う状態が表現できてしまう。

状態・出来事の表を読む部分は `mail.rs` の関数に括り出して `slot` と共有する。後の段で共通の形に移す。

軸: 表現不可能 — 「過ぎた」を状態に持たず、終了時刻から毎回導く。

### D5: Quint の仕様は書かず、語彙から読んだ遷移表の全マスを試験する

`mail` の仕様が検査する性質(終端から戻らない、スレッドごとの未了は 1 つ、`stale` の前に `remind`、
答えが無くてもいずれ終端、読み直しで重複しない)は、並行する機体の同期、機械が書く出来事、対象横断の条件が
作る。作業の枠にはタイマーも、機械の書き手も、対象横断の条件も無い。残る性質(終端から出ない、許されない
遷移が弾かれる)は、語彙の遷移の有向グラフだけで決まる。検査は試験で行う: 語彙 JSON から読んだ表の全マス
(状態 `none`・3 状態 × 出来事 4)について、実装が表のとおり通す・弾くことと、終端から出る出来事が無いこと、
畳み込みが行の読み込み順に依らず決定的なこと(時刻の違う 5 行の全順列 120 通り)、同じ鍵の再 `plan` が
拒否されること、`overdue` の境界(終了ちょうどは過ぎていない)を確かめる。

軸: 検出のみ — 試験は表と実装のずれを検出するが、ずれを書けなくはしない。

### D6: 終端の控えと `restore`・`forget` は作らない

`mail` の控え(機体ごとの JSON Lines)は、終端の行が手で消えたとき、読み直した受信が通常の未了に戻って
`sweep` が再通知する暴走を、検出して止めるためにあった。作業の枠には、無人で書く `sweep` が無い。終端の行が
消えれば枠は `scheduled` に戻り、終了を過ぎていれば `overdue` に、過ぎていなければ `open` に出て、
本人に見える。本人が裁き直せば直る。控えを持たないので、`restore`・`forget` も要らない。`plan` の行が
消えて後続の行が残った場合は、`check` が「開いていない枠への …」を食い違いとして出す。

軸: 還元 — 控えが担っていた仕事(無人の再通知の抑止)が、この対象には無い。

## 先行例との対比

- D1: 作業の枠の状態を、新しい台帳を作らず、`slot` kind の行を出来事として畳み込んで決める。
  先行例: ADR-1259 D1(未裁定のメール項目を `mail` 行の畳み込みで追う) docs/adr/1259-mail-lifecycle.md (取得 2026-10-30)
  差分: 一致 — 出来事の置き場も書き込み口も同じで、kind と語彙だけを足す。
  既存手段: crates/worklog/src/mail.rs — 拡張: crates/worklog(mail kind と同じ作りで slot kind を足す)
  軸: 還元 — 書き込み口が既にある仕事のために、同じ仕事をする口を増やさない。
- D2: 新しい kind の名前を、既存の自由記述の `task` と分けて `slot` にする。
  先行例: `Kind` 閉語彙(kind を足すと、各 kind が自分の文法を持つ) crates/worklog/src/lib.rs (取得 2026-10-30)
  差分: 一致 — `task` を再利用せず、新しい名前で足す。
  軸: 表現不可能 — 自由記述の行と文法つきの行を同じ kind に混ぜない。
- D3: 時間枠と参照 Issue を行に持ち、鍵を枠の id にして、使い回しを許さない。
  先行例: ADR-1259 D4(鍵を設計し、冪等性と重複しない性質を鍵に持たせる) docs/adr/1259-mail-lifecycle.md (取得 2026-10-30)
  差分: 異なる — 受信は外から届き読み直しが同じ鍵になるが、枠の id は自分で決めるので、鍵は使い回せない。時間枠を行に持つ点は新しい。
  軸: 表現不可能 — 終了が開始より前の枠、オフセットの無い時刻、使い回された鍵を書けなくする。
- D4: 語彙を `mail` と別の JSON にし、タイマーを持たず、「過ぎた」を導く値にする。
  先行例: ADR-1259 D2 と D5(語彙 JSON 1 枚を正本にし、時間の決まりを `timers` に置く) docs/adr/1259-mail-lifecycle.md (取得 2026-10-30)
  差分: 異なる — タイマーを持たず、時間に依る値(過ぎたか)は状態にせず導く。
  軸: 表現不可能 — 時刻と状態が食い違う状態を表現できなくする。
- D5: Quint の仕様は書かず、語彙から読んだ遷移表の全マスを試験する。
  先行例: ADR-1259 D7(仕様の軌跡を実装の畳み込みに通して一致を確かめる) crates/worklog/tests/itf_replay.rs (取得 2026-10-30)
  差分: 異なる — 仕様を書かないので軌跡の再生は無く、表から実装を直接試験する。仕様を要した条件(並行・タイマー・対象横断)がこの対象に無いことは、D5 に書いた。
  軸: 検出のみ — 試験は表と実装のずれを検出するが、ずれを書けなくはしない。
- D6: 終端の控えと `restore`・`forget` は作らない。
  先行例: ADR-1259 D6(終端の行の手削除を機体ごとの控えで検出する) docs/adr/1259-mail-lifecycle.md (取得 2026-10-30)
  差分: 異なる — 控えが防ぐ無人の再通知が無いので、控えを作らない。
  軸: 還元 — 控えが担っていた仕事が、この対象には無い。

## 却下した案

- `task` kind に文法を課す。D2 のとおり、既存の自由記述の行が壊れる。
- 予定データ(Git の TOML)に置き続ける。作る・済んだ・組み直す・やめる、のたびに PR が要る。
- `overdue` を状態にして、機械が書く。時刻と状態が食い違えるようになり、無人の書き手が要る。
- `mail` と同じ語彙ファイルに足す。対象が違い、`timers` の有無も違う。共通の形は後の段で作る。
- Quint の仕様を書く。D5 のとおり、検査する性質が語彙のグラフだけで決まる。
- 終端の控えと `restore`・`forget` を移す。D6 のとおり、控えの仕事が無い。

## Consequences

- 作業の枠の状態は、vault の当日ノートの `[slot]` 行から引ける。`worklog slot open` が未了、
  `worklog slot overdue` が終了を過ぎた未了を出す(TSV と `--json`)。読む側の変更は後の段で行う。
- 切り替え日(`2026-10-30`)より前のノートの `[slot]` 行は畳み込まない。読む範囲は `list` の上限(400 日)に
  収まる分までで、それより前に `plan` して未了のままの枠は見えなくなる。
- 限界: 終端の行の手削除は検出しない(D6)。同じ日のノートに同じ `resched` の行は 2 度書けない
  (A → B → A と同じ日に組み直すと止まる。翌日なら書ける)。要旨を持たないので人名は書けないが、鍵に
  人名を書くことは検出できない。
