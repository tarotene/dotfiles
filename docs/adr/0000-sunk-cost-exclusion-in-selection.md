# ADR-0000 — 技術選定の裁定から歴史的経緯と書き直しの作業量を除く

- Status: Accepted
- Date: 2026-10-08
- Issue: No-Issue(`/grill-me` セッション中の依頼から始まった。「LLM がよく何も考えずに Python を採用する癖があると思っていて、かつ技術スタックの移転等を検討する際にいちいち書き直しコストを考慮することも相まって初期の技術スタックの選定が Sticky に影響するのを根本からやめさせたい」)。再裁定の Issue は #750

## Context

依頼は 2 つの癖を指していた。前半は LLM が考えずに特定の言語(Python)を採ること、後半は
技術スタックの移転を検討するたびに書き直しコストを数え、初期の選定が後の裁定まで粘着する
(sticky)こと。前半は「仕方ない」とされ、後半を断つポリシーを求められた。方針は次のとおり:
歴史的経緯でしかないものは考慮せず、書き直しコストは常に 0 とし、コード 0 行の状態で
正しさ・クリーンさだけを考慮するとしたら何を採るか、だけで裁定する。

既存の規範を読むと、コストを理由にする文言が 4 か所にあった。

- **ADR-0035 D3**(重い欄の条件): 「撤収コストが導入コストを上回る選択」。
- **ADR-0035 D4**(節名を改名しない): 「波及コストに対して得られるのが名前の正確さだけ」。
- **共有 AGENTS.md** の還元性: 「あとで消すコストより今消すコストの方が小さい」。
- **ADR-543**(Q1 の前倒し): 「自前実装は育つほど撤収コストが上がる」。

これらは今回の方針と干渉する。ただし干渉の質が違う。前の 3 つは「何を採るか」の裁定の
入力にコストを入れている。ADR-543 は「いつ問うか」という手順の設計の根拠で、裁定ではない。
この違いが、整理の分け方になった。

先行研究(書誌は Crossref で照合した、取得 2026-10-08):

- Hal R. Arkes, Catherine Blumer, "The psychology of sunk cost", Organizational Behavior and
  Human Decision Processes 35(1):124-140, 1985, <https://doi.org/10.1016/0749-5978(85)90049-4>。
  すでに払った費用を意思決定に持ち込む誤りの実験的な記録。
- William Samuelson, Richard Zeckhauser, "Status quo bias in decision making", Journal of Risk
  and Uncertainty 1:7-59, 1988, <https://doi.org/10.1007/BF00055564>。現状を選ぶ偏りの記録。
- Peter A. Pyhrr, "The Zero-Base Approach to Government Budgeting", Public Administration
  Review, 1977, <https://doi.org/10.2307/974503>。毎期を白紙から見直すゼロベース予算。

## Decision

### D1: 0 とみなすのは作業量だけ

書き直し・波及する編集・レビュー量・テストの移し替えを 0 とみなす。「すでにこうなっている」
という歴史的経緯は理由にしない。**数えるのは戻せないものだけ**: 失うと戻せないデータ、自分では
管理できない外部の利用者との契約、人手でしかできない作業。実在する制約を無視すると、白紙の
上の裁定が現実から外れるため。

### D2: 新しい軸にせず、3 軸の評価の前提条件にする

ADR-0035 の 3 軸(表現不可能性 → 還元性 → 先進性)は変えない。評価の前に、入力から歴史的経緯と
作業量を除く。判定質問は「コード 0 行の白紙から選ぶとしたら、3 軸で何を採るか」。現職も
白紙の上では候補の 1 つで、特別扱いしない。ADR-0035 が「先進性」を独立の基準にせず
軸 1 の同順位破りに留めたのと同じ考え方で、独立の軸を増やさない。

### D3: 完全に同点なら現職を維持する

白紙で比べて 3 軸すべてが同点なら現職を維持する。理由は「乗り換えてもどの軸も良くならない」
ことだけで、乗り換えの手間や使い慣れは理由にしない。変更を提案する側が、どの軸がどう良くなるか
を示す。

### D4: 裁定と実行を分ける

乗り換えるべきという裁定が出たら、結論を Issue に「意図は決まっていて未着手」として残す。
いつ移行するかは自由。「コストが高いから移行しない」という裁定は残せない。ADR-0035 D5
(既存の選択を自分から棚卸しする義務は課さない)は維持する。

### D5: 擬制は裁定にだけ使い、手順の設計には使わない

作業量 0 の擬制は「何を採るか」の裁定にだけ使う。ADR-543 の前倒し(Q1 を着手の瞬間に問う)は
手順の設計であり、作業量の現実を前提にしてよい。ADR-543 は変更しない(Amendment で 1 段落、
補い合う関係だと書き足す)。前倒しは、裁定は決まったのに移行されない状態の積み上がりを抑える。

### D6: 重い欄の条件を差し替え、実装言語の選択を足す

ADR-0035 D3 の重い欄(`本命:`/`対抗馬:`/`外した候補:`)の条件を、「外部依存の新設・置換・撤去、
新しい道具・単位の実装言語の選択、または戻せないものが生じる選択」にする。実装言語の選択を
足したのは、前半の癖(考えずに特定の言語へ倒れる)に対抗馬を立てさせるため。Python を選んで
よいが、白紙で同じ軸の上で比べた記録を残す。新しい gate は作らない。

### D7: 機械的な強制を既存の gate に足す

`plan-precedent-gate` に 2 つを足す。

- 閉じたトークン `戻せない: データ|外部契約|人手 — <内容>`。コストを理由にしてよい唯一の書き方。
  値が閉語彙の外なら deny。
- `Dn` ブロックに閉語彙のコスト語(書き直しコスト・書き直す手間・移行コスト・移行の手間・
  撤収コスト・波及コスト・乗り換えコスト・battle-tested・歴史的経緯)があれば deny。範囲は
  `## 先行例との対比` の `Dn` だけで、バッククォートで囲んだ語は引用なので数えない。
  英語の語は入れない(先行例の書誌、たとえば論文名の `sunk cost` を誤検知するため)。

### D8: 既存の規範と裁定の整理

- 今も有効な規則文は、この変更で書き換える: 共有 AGENTS.md(前提の追加、還元性の言い回し)、
  `config/claude/CLAUDE.md`、2 つの skill、設計文書、リポジトリの `AGENTS.md` の
  "battle-tested"(理由を還元性に)。
- ADR-0035 と ADR-543 には Amendment を付ける(上の D5・D6)。
- 理由が作業量だけだった既存の裁定は、白紙で裁定し直す Issue として #750 に列挙する。ADR の
  Alternatives は当時の記録なので書き換えない。

## Alternatives considered

- **第 0 軸として先頭に足す。** 棄却。作業量の除外は評価の「入力」の話で、軸(評価の
  観点)ではない。軸にすると、軸 1〜3 と並べて同点・衝突の規則が要る。
- **還元性(軸 2)の文言を書き換えて収める。** 棄却。還元性は「より安い手段で足りるか」を
  問う軸で、評価の入力を変える前提条件とは役割が違う。ADR-0035 の Amendment 1 本に押し込むと、
  ADR-543 や AGENTS.md に効く横断的な前提が見えなくなる。
- **移行にかかるもの全部を 0 とする(データ・契約を含む)。** 棄却。戻せないデータの損失や
  外部契約の破壊を無視すると、白紙の上の裁定が現実に着地しない。
- **コスト語の lint を置かず、規範の文言だけにする。** 棄却。同じ違反が既に 4 本の ADR
  (ADR-0035 D4、ADR-568、ADR-625、ADR-0033)で繰り返されている。ADR-543 の「繰り返したら
  昇格する」に当たる。
- **LLM の critic に判定させる。** 感触で外した(決定論で拾える閉語彙があるため)。分析ではない。
- **全部の既存の裁定をこの PR で裁定し直す。** 棄却。ADR-0035 D5 と、1 PR の範囲を保つため。

## Consequences

- 技術選定の裁定では、書き直しの作業量と歴史的経緯を理由に書けない。書こうとすると gate が
  deny し、`戻せない:` の閉じた形に誘導される。
- 既知の限界(検出のみ): lint は閉語彙の語だけを拾う。言い換え(「手間がかかる」等)は
  すり抜ける。内容の妥当さは lens A(copilot-plan-review)が見る。計画の外(PR 本文・コメント)の
  文言は検査しない。
- 完全に同点なら現職を維持するため、白紙の評価が「現職の追認」に化ける余地がある。対抗馬を
  同じ軸で比べた記録を重い欄で残させることで抑える。
