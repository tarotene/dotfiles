# ADR-1701 — ページの型の要件は、検査の種別つきのデータに起こし、描画した HTML で測れるものだけを機械で検査し、測れないものを「通った」にしない

- Status: Accepted
- Date: 2026-11-24
- Issue: No-Issue(ADR-1677 D5 が「次の ADR 以降」に残した、ページの型の要件の起こしと検査。Web の面を基準に従わせる作業の、計画の段3)

## Context

ADR-1677 D5 は、最初のページの型を 3 つ(学習・演習、裁定フォーム、ダッシュボード)と決め、要件は「出力した HTML を機械で検査できる文にする」と定めた。要件の起こしと検査の実装は、次の ADR に残した。

実機の審査(2026-11-24。描画せずにコードだけを読む評価者 3 人)は、面ごとにばらばらな指摘を、次の型にまとめた: 保存の成否が利用者に返らない、ショートカットのキーがボタンの標準のキー操作を奪う、読み込み中・失敗・空の区別が無い、暗色で固定色の文字が淡い色の上に載る、スマートフォンで完結しない操作。人が読んで見つけたものは、面を変えるたびに、人が読み直さないと再発に気づけない。

## Decision

### D1: 要件は `config/web/page-types.toml` に、型(共通・学習・演習・裁定フォーム・ダッシュボード)ごとの一覧として置く。各要件は、検査の種別を 1 つ持つ(閉じた語彙)

種別は 3 つ。`audit`(描画した HTML を `visual_diff.py audit` が機械で検査する。検査の名前を持つ)、`walkthrough`(認知的ウォークスルーの 4 問で人が通す)、`visual`(撮影した画面を人が見る)。キーは閉じていて、知らないキー・語彙の外の種別・`audit` の名前を持たない `audit`・`audit` でない要件の `audit` の名前・要件 ID の重複・どの要件にも結びつかない検査は、読み込みで落ちる(`load_types`)。面は、撮影定義の `types = ["common", "form"]` で、当てはまる型を宣言する(省略は `common` だけ)。

先行例: ADR-1677 D5(要件は、出力した HTML を機械で検査できる文にする。軸は検出のみ)。ADR-1660 D4(検査できる型として宣言する)。
差分: 一致 — ADR-1677 D5 の要件の起こしを、データとして実装した。異なる — 「機械で検査できる文」だけでなく、機械で測れない要件を、同じ一覧に種別つきで残す。
軸: 表現不可能 — 閉語彙 > 自由記述 + 事後 lint。検査の種別と名前を閉じ、結びつかない検査や、名前を持たない `audit` を、書けない形にした。

### D2: 描画した HTML で測れる要件(10)だけを `audit` にし、描画した状態ごと・明暗ごと・幅ごとに測る

ADR-1677 D5 は静的な HTML の検査を想定したが、ショートカットのキーがボタンの標準のキー操作を奪うかは、静的には読めない。`audit` は、撮影と同じ行列(明暗 × 幅 390px・1280px × 撮影定義の状態)で、ページの中の測定(文字のコントラスト・操作部の大きさ・横スクロール・`lang`/`title`/`main`/`h1`・主操作の数・初期状態で選択済みのラジオ)と、実際のキー操作(ボタンにフォーカスして Enter・Space を押し、押されるか)と、遮断した第三者への要求と、開いた確認ダイアログを見る。`confirm(` の静的な検出も足す。機械で測るのは C1・C2・C3・C4・C9・C12(共通)、F1・F2・F4(裁定フォーム)、D7(ダッシュボード)。違反は、要件・説明・出たセルの一覧で出し、終了コードは違反があれば 1。

先行例: ADR-1677 D5。`docs/agents/personal-web-app.md` §6(操作の規則。ショートカットは標準のキー操作を奪わない、操作部は 24×24px 以上、など)。WCAG 2.2 の SC 1.4.3・2.5.8・2.1.1 https://www.w3.org/TR/WCAG22/ (取得 2026-11-22。別の調査の記録から)。
差分: 異なる — 静的な HTML でなく、描画した状態に対して、実際にキーを押して測る。ラベルで囲まれたラジオ・チェックボックスは、押せる範囲がラベルの行全体になるので、ラベルの大きさで測る(撮って気づいた誤検出を直した)。
軸: 検出のみ — 要件を満たさないページを作れなくはしない。ADR-1677 D5 と同じ。

### D3: 機械で測れない要件を、「通った」にしない。検査の出力に、人が見る要件を「未検査」として並べる

`audit` の出力は、違反・通った検査・人が見る要件(`walkthrough`・`visual` の ID とその種別)を、面ごとに並べる。通った検査の一覧は、機械で測った要件だけで、測れなかった要件は、通った一覧に入らない。

先行例: 本人の裁定(2026-11-24。見た目の確認では、初期状態だけで撮り終えない。測れないことを、確かめたことにしない)。ADR-1687 D3 の軸の注記(検査が届かない範囲を「未実装(意図あり)」と書く)。
差分: 一致。
軸: 検出のみ — 人が見る要件が、実際に見られたかは、機械で強制できない。

## Alternatives considered

D2 では、axe-core(npm)をそのまま使う案を外した — 感触で外した(npm の依存の木を足したくない。README は読んでいない)。主操作の数・初期状態の選択・ショートカットのキーの奪い合いのような、このページ群の要件は、汎用の検査の規則にも無さそうだが、確かめていない(未確認)。D1 では、要件を ADR の本文だけに書く案を外した — 検査が読める形にならず、型の追加・面の宣言を、機械が検証できない(分析)。

## Consequences

- 面は、撮影定義に `types` を宣言する。検査は手元で `visual_diff.py audit` として走り、CI では、`--selftest`(要件の読み込みの検査と、測定から違反を作る関数の試験)が走る。撮影を伴う検査(悪いページが 10 の検査のすべてで落ちる)は、`--selftest --browser` で、手元で走らせる。
- `audit` を CI で面に対して走らせること(ブラウザが要る)は、この ADR の範囲外(未実装、意図あり)。
- 要件の文は、公開の基準(WCAG 2.2・NN/g のヒューリスティック・デジタル庁デザインシステム・GOV.UK など)から起こした。学習・演習の要件(L2・L4 など)は、学習科学の文献からの推論で、出典の文そのものではない。

## Verification

- `uv run --script config/agents/skills/pr-description/scripts/visual_diff.py --selftest`(ブラウザ無し): 要件の読み込み(実物の 4 つの型・38 の要件、9 種の誤りの拒否、全検査の結びつき)と、測定から違反を作る関数(基準を満たすセルは違反なし、外れたセルは 10 の検査のうち keyboard 以外のすべてが違反、型が持たない検査は数えない、Artifact の断片は `lang`・viewport を求めない、選択済みのラジオは初期状態だけ、`confirm(` の静的検出)が成功。
- `--selftest --browser`: わざと悪いページ(`lang`・`title`・`main`・`h1` なし、薄い文字、小さいボタン、横にはみ出す要素、第三者の画像、キーを奪うボタン、主操作が 2 つ、選択済みのラジオ、`confirm(`)が、10 の検査のすべてで落ち、良いページ(ラベルで囲まれた小さいラジオを含む)がすべてを通り、キーを奪うボタンだけが、キー(Enter・Space)の名前つきで拾われる。
- 実物への適用: 見本ページ(型 common)は違反 0 件(6 検査が通り、8 件は人が見る)。裁定ページ(型 common と form)は違反 8 件で、同日の実機の審査が人の目で見つけた型と同じものを、機械が出した: 選択肢のボタンで Space がボタンを押さず(Enter は押せる)、幅 390px で横スクロールが出て、24px 未満の操作部(`summary`・リンクの見た目のボタン)がある。
- 未実施: CI での実行(この PR の CI で確かめる)。
