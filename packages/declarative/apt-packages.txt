# --- Input method: client-side immodules ONLY ---
#
# The fcitx5 daemon and the mozc engine moved to home-manager (Amendment to
# ADR-0001): apt caps fcitx5 at 5.1.7, which predates the fix for the trigger-key
# defect in docs/ime-chrome-diagnosis.md / #14.  What stays apt is the client half
# — an apt GTK/Qt application can only load an immodule out of /usr/lib, and
# ghostty and Firefox both do (verified: im-fcitx5.so in their /proc/*/maps).
#
# fcitx5-frontend-all is listed EXPLICITLY even though it is already installed,
# because it arrived as a Recommends: of fcitx5 and is therefore apt-mark auto.
# Measured, not assumed — `apt-get -s autoremove fcitx5 fcitx5-mozc
# fcitx5-config-qt` on company-pop-new removes 35 packages including all four
# fcitx5-frontend-{gtk3,gtk4,qt5,qt6}, libfcitx5gclient2, libfcitx5-qt1 and
# libfcitx5-qt6-1: the entire immodule stack, which would silently kill Japanese
# input in every apt application.  The frontends themselves depend only on those
# libraries, never on the fcitx5 binary package, so a plain `apt remove fcitx5`
# leaves them alone; it is autoremove that is dangerous.  install-packages.sh
# apt-installs each listed name, which marks it manual and protects its
# dependency closure.
fcitx5-frontend-all
