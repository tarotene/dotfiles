依頼者が「敵対的レビューをぶつけて」「先行例・文献を調査してから」と
毎回書かなくても済むように、Plan mode の設計判断には常に先行例接地の
結果を書く。詳細な設計動機と文献根拠は `docs/adr/0012-precedent-
grounding-over-prompted-adversarial-review.md` と
`docs/claude/precedent-grounding.md` を参照。

要点: 「敵対的に見よ」という抽象指示ではなく、設計判断ごとに
検証可能な 1 行を書く。批評は文脈を切った critic(copilot-plan-review
の lens A)が、その行を根拠に監査する。

## 1. 非自明な設計判断の見つけ方

「妥当な代替が他にも存在し、その中の一つを選んでいる箇所」だけを拾う。
典型例:

- 機構の選び方(hook / skill / CLAUDE.md / ADR のどれに置くか)
- 配置・分割の仕方(1 ファイル vs 複数、stacked PR の段の切り方)
- 命名・語彙(既存の `-gate`/`-guard`/`-allow` のような規約に沿うか)
- プロトコル・データ形式(JSON スキーマ、gate の判定条件)
- アルゴリズム・手法(研究的性質を持つ問題)

対象**外**: typo 修正、既存パターンをそのまま適用するだけの変更、
唯一の実装方法しかない配線作業。これらは Plan 全体を通じて非自明な
設計判断がなければ、節ではなく 1 行の免除で済む。

## 2. 出典の優先順位

`config/claude/CLAUDE.md`「発明する前に先行例を確認する」と同じ順:

1. 一次情報源(公式ドキュメント・upstream ソース/spec・学術文献)
2. 組織内の先行実装・過去の決定(この dotfiles リポジトリ内の
   `docs/adr/`・既存の hook/skill・過去の Issue/PR が最優先。同じ
   リポジトリ内で答えが見つかるのに外部を探すのは遠回り)
3. 二次情報(ブログ等)は 1–2 の裏取りがある場合のみ

外部の一次情報(論文・公式ドキュメント)を要する調査は、本線を止めない
ため `research` スキルで background agent に委譲する。検索クエリに
会社固有の識別子(社名・非公開プロジェクト名)を入れない。

## 3. 節の文法

```markdown
## 先行例との対比

- D1: <採った設計判断を 1 文で>
  先行例: <著者/組織, タイトル, 公開日> <URL | リポジトリ内パス | #N> (取得 YYYY-MM-DD)
  差分: 一致 | 異なる — <理由>
- D2: <採った設計判断を 1 文で>
  先行例なし: <探した範囲(どこを・何のキーワードで・一次/二次のどちらまで)>
```

- `Dn` は要求インベントリの `Rn` と同じ発想の ID。設計判断 1 つ = 1 行。
  重複させない。
- `先行例:` 行には出典トークン(URL、リポジトリ内パス、`#N` の Issue/PR
  番号のいずれか)と `(取得 YYYY-MM-DD)` を必ず書く。取得日は捏造せず、
  実際にこのセッションで読んだ日にする。
- `差分: 一致` は先行例の判断をそのまま採った場合。`差分: 異なる` は
  先行例から意図的に外れた場合で、理由を書く(ADR-0012 の
  「Alternatives considered」と同じ役割)。
- `先行例なし:` は探したが見つからなかった場合。「探さなかった」の
  言い換えにしない — 実際に探した範囲を書く。
- 設計判断を含まない Plan は節そのものを省略し、代わりに 1 行:
  ```
  先行例: 該当なし — <理由(例: 既存スクリプトのバグ修正で設計判断を含まない)>
  ```

## 4. 批評者(lens A)が監査すること

`copilot-plan-review.sh` の lens A は、この節の各 `Dn` について:

- 出典(リポジトリ内パスや Issue/PR は実際に読む)が主張を実際に支えて
  いるか
- `差分: 異なる` の理由が成立するか(単なる好みではないか)
- `先行例なし:` の探索範囲が、その設計判断の重要度に見合っているか
- 節に載っていない非自明な設計判断が Plan の他所に紛れていないか

を見る。**出典を示せない「もっと良い代替案があるかもしれない」型の
指摘は報告しない** — これは open-ended search を助長し、CLAUDE.md の
方針とも文献(ADR-0012)とも矛盾する。severity の目安は、理由のない
逸脱は MAJOR、引用した先行例と矛盾して要件を満たさなくなる場合は
BLOCKER。

## 5. アンチパターン

- 出典のない一般論(「〜という考え方が一般的」)を `先行例:` の内容に
  書く。出典トークンが無ければ節の要件を満たさない。
- 二次情報(個人ブログ・まとめ記事)だけを出典にする。一次情報の裏取り
  がないなら `差分:` ではなく `先行例なし:` として扱う。
- このセッションで実際に読んでいない URL や、記憶からの推測で書いた
  取得日。読んだ範囲だけを書く。
- 「先行例: 該当なし」を、探すのが面倒だったときの言い換えに使う。
  免除は「設計判断そのものが存在しない」ときだけ有効。
