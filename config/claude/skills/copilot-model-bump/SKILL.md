外部 AI CLI（レビュー hook の critic、生成 agent 等）に `--model` で明示 pin してある具体モデル ID は、ベンダー側の GA・廃止サイクルに合わせて定期的に追従する必要がある。pin 箇所を総当たりで洗い出さずに1箇所だけ書き換えると、selftest やドキュメントに旧 ID が残ったまま気づかれず、契約テストが偽の安心感を与える。

## 1. pin 箇所の棚卸し（変更前に必ず grep）

具体モデル ID は最低でも次の場所に重複している。1回の grep で全部を列挙してから着手する:

- 呼び出し本体の既定値（`${VAR:-<model-id>}` のような env var フォールバック）
- selftest 内の「既知値へ固定し直す」ブロック（ホストの env を上書きして真の初期値を再現する箇所）
- selftest が偽コマンド（フェイクバイナリ）に期待させる契約値（`FAKE_*_EXPECT_MODEL` 等）
- selftest のラベル文字列自体（`"契約: --model の既定は <model-id>"` のような、期待値がラベルにも埋め込まれているケース）
- 設計ドキュメント内の呼び出し例・環境変数表・「調査時点で利用可能な最新モデル」という記述

grep 1回の結果に出てこない箇所は変更対象から漏れているだけで「無い」わけではない、と疑う。旧 ID・旧 CLI バージョン番号の両方を検索語にする。

## 2. 上流確認（発明する前に一次情報を見る）

1. **CLI 側の互換性**: `<cli> --help` で、hook が渡している全フラグが現行バージョンでも存在するか確認する。フラグ名が変わっていないなら「モデル ID の差し替えだけ」で済むと判断してよい。
2. **モデルカタログの現状**: ベンダー公式の changelog / supported-models ドキュメントで次を確認する:
   - 新モデルが GA しているか、CLI で使えるか（プレビュー限定でないか）
   - 現在の pin 先が廃止（deprecation）ウェーブの対象に入っていないか、入っているなら期限はいつか
   - 同世代に複数バリアント（速度/コスト/推論力のティア違い）があるなら、それぞれの位置づけ
3. 二次情報（ブログ等）は上記1次情報の裏取りとしてのみ使う。

## 3. 選定基準

pin 先を1つに決める際は、hook が critic に要求している役割に照らして選ぶ。典型的な軸:

- **役割適性**: 検証・長期タスク向けの critic なら高い推論ティアを優先する（速度/コスト優先の軽量ティアは避ける）
- **クロスベンダー独立性**: レビュー対象（プランや実装）を書いたモデルと同一ベンダー・同一系統のモデルを critic に据えると、盲点が一致しやすい。既存設計がベンダー分離を意図しているなら、その意図を壊さない選択をする
- **課金方式**: 定額課金かリクエスト従量課金か、倍率が特別に高くないかを確認する

## 4. スラッグ実機確認（安価な検証）

多くの CLI は、無効なモデル ID を渡すとリクエストを送信する前に即座にエラーを返す。这を使って、本番プロンプトを送る前に候補スラッグの有効性を安価に確認できる:

```bash
<cli> -p "reply with OK only" --model <candidate-id> --silent --no-ask-user </dev/null
```

エラーなら別の命名パターンを試す。成功したら以降の変更に進む。

## 5. 変更は3箇所を同時に

1. 呼び出し本体の既定値
2. selftest の期待値（固定し直しブロック・フェイクバイナリの契約値・ラベル文字列の3種すべて）
3. 設計ドキュメント（既定値の表、呼び出し例、「なぜこのモデルか」の記述、旧 pin からの変更経緯を1-2行）

ドキュメント中の「実機 x.y.z で確認済み」という技術事実の記述は、モデルが変わっても CLI バージョンが変わらなければ書き換えない。CLI バージョンも上がっている場合は、古い実測記録を消さずに「新バージョンでも再確認済み」を追記する（実測の来歴を保つ）。

## 6. 完了条件

次の3つが揃うまで完成と呼ばない:

- `--selftest`（または相当する回帰テスト）が新しい pin 値で全通過する
- lint（shellcheck 等）がクリーンである
- 実機で1回、新モデルに対して非ゲート消費の経路（advisory / dry-run 相当）を実行し、スキーマ適合の応答が返ることを確認している

grep で旧モデル ID が1件でもヒットする状態は未完了とみなす。
