# 事例集

## README に残った「まだ実装していない」記述が、実装後も独り歩きした(zombie limitations)

別のリポジトリの README 保守で見つかったパターン。「まだ実装していないもの」を
書いていた記述(本スキーマでは `## Scope` の caveats に相当する箇所)が、
それを実装した PR とは別のコミットで放置され、実装完了後も存在しない制約と
して残り続けた。新規ユーザーや将来の contributor がその記述を真に受けて誤誘導
される「zombie limitations」状態になっていた。

ADR-0016 の固定 README スキーマに `## Limitations` という見出しは無い(許可外
見出し)が、同種の「まだ担っていないこと」の記述は `## Scope` の地の文
(caveats)に現れる。実装が進んでも Scope 節を更新しないと同じ腐敗が起きる。

**教訓**: 「まだやっていない」を書く記述は、実装した PR と同じコミットで
更新・削除しないと、存在しない制約が正本として残り続ける。

**チェックリスト(実装 PR ごと)**:
1. 実装する機能について README 内の言及を検索する(`grep -r "keyword" */README.md`)。
2. この PR が実現する内容を Scope の caveats が記述していれば、同じコミットで
   削除・更新する。
3. 部分的にしか実装していない場合は、残っている制約を反映するよう書き換える
   (元の文言を残さない)。
4. 先送りにするサブタスクがあるなら、親 Issue を閉じる前に GitHub Issue を
   起票する(追跡は Issue 側で足り、README の Scope に個別 Issue 番号は
   書かない — ADR-0016 の永続性原則)。

## README の同期義務が、実際に重複を発火させ続けた(ADR-0033 の発見事例)

別の private リポジトリ(具体名は `docs/claude/public-publish-guard.md`
の方針により伏せる)の README・AGENTS.md を調査した結果、AGENTS.md に
「README は同じ標準を human-readable に要約せよ、両者を同一コミットで
更新せよ」という同期義務が明文で存在していた。これは一見 ADR-0016
Decision 5(AI 向け正本は AGENTS.md、README は参照する側)を守ろうとする
善意の規定に見えるが、実際には「要約」の名の下に AGENTS.md の内容を
README へ複製する義務そのものだった。

調べた時点で実際に 6 件の drift(README の一覧・スキーマ記述が実体から
乖離)が発生しており、調査セッション中にも AGENTS.md への追記のたびに
README・サブディレクトリ README の双方に同じ内容が同時追記される場面が
observed された。「要約して」という指示は、時間が経つほど元の文言に
近づいていく(要約のつもりで書いた文が、次の改訂では前回の文言をコピペ
して微修正する運用に落ち着く)。

同じ調査で、ディレクトリ構成図(`tree` 相当のコードブロック)・ADR 索引・
YAML スキーマの転記も見つかり、いずれも実体と乖離していた(構成図から
複数ディレクトリが欠落、ADR 索引から複数 ADR が欠落、スキーマ転記が
実ファイルの現行フィールド構成に未追従)。

**教訓**: 「README は AGENTS.md/実体の要約であるべき」という規定は、
それ自体が二重管理を強制する。ADR-0033 のとおり、要約ではなく**参照**
(1 行ポインタ)にする。ディレクトリ構成図・コンテンツ一覧・他ファイルの
転記は、書いた瞬間から寿命が始まる負債であり、どれだけ「同一コミットで
更新する」と規約に書いても、人力での同期は長期的には必ず漏れる。

**チェックリスト(適合化 PR ごと)**:
1. AGENTS.md や他の導線文書に「〜を要約せよ」「〜と同期させよ」という
   規定がないか検索する。あれば削除し、参照方向を片方向(正本 →
   ポインタ)に固定する。
2. `github-audit charters` の `nav-doc-*` 系トークンで機械的に洗い出す
   (詳細は `docs/adr/0033-nav-doc-no-materialisation.md`)。
3. 削除した情報の退避先(`<dir>/README.md` の冒頭 1 文、または実体
   ファイル自身のコメント)が実在することを確認してから削除する —
   情報を消すだけで終わらせない。
