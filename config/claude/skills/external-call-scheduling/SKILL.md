外部窓口への電話のように、時間帯制約(相手の営業時間・受付時間)を伴い、かつ
Claude 自身が実行できない作業をユーザーに引き継ぐとき、トークスクリプトを
文書に書いて渡すだけでは「ユーザーが忘れずに実行できる」保証にならない。
ユーザーは他の作業に気を取られており、営業時間内に自発的に思い出す確率は
低い。

## いつ発動するか

- 電話・来店・窓口対応など、Claude が代行できない作業をユーザーに依頼する場面
- その作業の実行可能時間帯が外部要因(相手の営業時間・定休日)で制限されている場面

会話内でトークスクリプトや確認事項を用意して終わりにせず、下記の手順まで
セットで行う。

## 何をするか

1. 対象の営業時間帯・定休日を洗い出す。
2. ユーザーの予定表を参照し、営業時間帯とユーザーの空き時間が重なる枠を探す。
   確定済みの予定(本番・出張・研修等、busy 相当のもの)と衝突しない枠を選ぶ。
   「予定が入っていないように見えるが実際には難しい時間帯」(移動中・休養日
   など)を機械的な空き判定だけで拾わない。
3. 見つけた枠にリマインダー予定を作成する。件名には対応が必要であることを
   一目でわかるマーカーを付け、説明欄には電話番号・確認事項の要点をその場で
   読めるように書く(別ファイルへの参照だけで済ませない)。
4. Claude が提案する予定専用のカレンダーが既に用意されている場合はそれを使う。
   無ければ、どのカレンダーに書き込んでよいかをユーザーに確認してから作成する
   (個人の主カレンダーに無断で書き込まない)。
5. その作業に前提条件(例: 別タスクの結果待ち)がある場合は、予定の説明欄に
   明記し、ユーザーが実行タイミングを自分で判断できるようにする。

## 外部サービスへの書き込みはサニタイズ対象

カレンダー・メール等の外部サービスに送る文章は、リポジトリ内に閉じた文章とは
別物として扱う。件名・説明欄にプロジェクト名やリポジトリ名、内部の Issue
番号、内部ファイルパスを書かない — 汎用の言葉で要件が伝わるように書き直す。
これは `skill-gardening` の「サニタイズ規則」と同じ判断だが、対象がこの
リポジトリの外(ユーザーの実カレンダー・実メール)である点が異なる。

## 事例

個人プロジェクトの実務整理タスクで、外部窓口への確認電話をユーザーに依頼する
際、相手の営業時間とユーザーの既存予定(公演・遠征等)を突き合わせて空き枠を
選び、カレンダーに登録した。最初はプロジェクト名や Issue 番号を含めた説明文を
書いたところ、外部カレンダーサービスへの private リポジトリ参照としてガードに
検知され、書き直しが必要になった。カレンダー・メール等、リポジトリの外に出る
文章にはリポジトリ内のドキュメントとは別のサニタイズ基準がかかることを示す
実例。
