発表は「語り」が主、スライドは語りの補助資料。構成・ストーリーと見た目は
不可分なので、正本は 1 つの Marp Markdown ファイルに置き、語りとスライドを
同居させる。練習用の原稿は正本から導出し、別ファイルに複写しない。

「スライドを作って」と言われたら、見た目の相談に入る前にこの手順で始める。
見た目に凝った HTML だけが欲しいと本人が言ったときは §6 へ。

## 0. 前提

- 正本は Marp Markdown 1 ファイル。先頭に `marp: true`(必要なら `paginate: true`、
  数式があれば `math: katex`)。語りは各スライドの末尾に置く HTML コメント
  `<!-- -->` に全文で書く。コメントの外がスライド、中が原稿。
- `command -v marp` で CLI の有無を確かめる。無い環境(web セッション等)でも
  正本は先に Marp Markdown で書き、派生だけを §6 の Artifact などに切り替える。
- 置き場所は依頼側のリポジトリ・ディレクトリ。このスキルは既定のパスを持たない。
  分からなければ 1 回だけ聞く。

## 1. 問診

AskUserQuestion で 1 回にまとめて聞く: 聴衆、持ち時間、場(口頭のみ / 投影 /
配布あり)、既存の素材、聴衆が次に下す判断(商談・面談なら、相手が何を決める
ために見るか)、スライドを単体で読む場面か(画面共有で口頭を補う、事前に配る)。
続けて**談話全体の主張を 1 文で**本人に書いてもらう。
書けないときは下書きを 2〜3 案出して選んでもらう。この 1 文が確定するまで
語りを書き始めない。

単体で読む場面なら、スライドは §4 でなく §4a の資料型で派生させる。語りが主で
聴衆が話を聞く場面(講演・LT)は、これまでどおり §4 の講演型にする。

## 2. 構成

節ごとに主張を 1 文で立て、順序を決めて本人に確認する。この段階ではスライドの
話をしない。構成は見た目より先に固める。

## 3. 語り

節の主張の下に、語りを全文の散文で書く。

- 文体は `writing-style` スキルでハブを解決し、register を「話し言葉」と宣言して
  その規則を適用する。
- **ホワイトボード試験**: 語りが図・数式・表に触れるときは、その内容を言葉で
  言い直す。「ご覧のとおり」だけで済ませない。スライドが無くても話が通ること。
- 持ち時間に対する分量は、本人が声に出して測って調整する。目安の数値は
  このスキルに書かない。

## 4. スライドを派生させる

語りの区切りに `---` を置き、各スライドを次の形にする。

- 見出し: その区間の主張を 1 文で。トピック名ではなく文にする。
- 本体: その主張の証拠を 1 つだけ(図・数式・表・1 つの引用)。
- 箇条書きは既定で使わない。本人が明示したときだけ許す。
- 枚数は語りに従う。枚数の都合で語りを削らない。

## 4a. 単体で読む場面(資料型)

商談・面談・社内説明の画面共有のように、語りが途切れてもスライドだけで通じる
必要があるとき、または事前に配るときの派生のしかた。読み手が専門外のことが多い。
§4 の講演型とは、本体の密度と具体語の置き場が逆になる。

- 見出しは、講演型と同じく主張の 1 文。小見出しに、そのスライドの役割(誰か /
  何を提供するか / なぜできるか / どう関わるか)を添えてよい。
- 本体は表と複数の証拠を許す。ただし 1 枚の主張は 1 つに保ち、1 つのセルで太字に
  するのは要点 1 か所までにする。
- 語りにしか無い具体語(手法名、略語の展開)は面に出す。専門語は、聞き手の語に
  言い換える。
- 構成は役割の順に置く: 誰か → 何を提供するか → なぜできるか(裏付け)→
  どう関わるか。裏付けの各項目には、どの提供内容を支えるかの番号を付ける。
- 最後は、聞き手が次に下す判断に要る情報と、こちらから聞くことで締める。
  「今日の目的」は先頭でなく末尾に置く。
- **素材の範囲で止める。** 他人のレビュー案や自分の下書きを採るとき、素材に
  ある主張だけを載せる。素材に無い手順・時系列・数値・標語は、聞こえが良くても
  採らない。採らなかった項目は、理由を採否の表に残す。

完成の条件: スライドだけを渡された人が、誰が何を提供でき、なぜそう言えるかを
自分の言葉で言える。

## 5. 派生物と完成の定義

```bash
marp --no-stdin --notes deck.md   # → deck.txt  練習用の原稿(プレインテキスト)
marp --no-stdin deck.md           # → deck.html 発表用(p キーでプレゼンタービュー)
```

`deck.txt` はスライド順の語りを連結したもので、境界は `---` 1 行になる。

完成の条件は次の 2 つ。

- `deck.txt` を通読して、単独の講演原稿として成立する。
- `deck.html` の各スライドが「主張の見出し + 証拠 1 つ」になっている。

配布を頼まれたときだけ `marp --no-stdin --pdf --pdf-notes deck.md`(語りが
ページごとの PDF 注釈として入る)または `--pptx` を使う。どちらもブラウザが要る。
動かなければ、その旨を伝えて HTML か原稿 .txt の配布に切り替える。ローカルの画像を
参照するデッキは、`--allow-local-files` を付けないと Marp が読み込みを止めて警告する
(任意のローカルファイルを読む設定なので、信頼できるデッキにだけ付ける)。

## 6. 本人が明示したときだけの別の描画

正本は常に Marp ファイルのまま。

- **見た目に凝った配布用 HTML**: `~/.local/share/frontend-slides/SKILL.md`
  (rev 固定の配備先)を読み、その手順の Mode A「All content ready」に、正本の
  スライド文言と図だけを素材として渡す。先に本人へ伝える: このツールの出力に
  スピーカーノートは入らず、プレゼンタービューも無い。
- **claude.ai で共有する**: Artifact の Slides 型に派生させ、各スライドの語りを
  そのスライドの `<aside>` に写す。派生先の HTML を直接直したときは、Artifact へ
  送ったのと同じファイルを手元(git)に控えとして残す。控えが無いと、差分もレビューも
  残らない。
- 配備先のパスが無いとき(別ホスト・配備前)は、その旨を言ってから
  https://github.com/zarazhangrui/frontend-slides の `SKILL.md` を読む。
