# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主な利用者は本人 1 人。毎日、スマートフォン(iPhone の Safari)と PC の両方で、短い時間に、裁定・1 日分の予定の確認と書き込み・演習・状況の確認を済ませる。
読み手が本人以外になる面(公開のサイト、団体の面)もあるが、最も長く触るのは本人が操作する面。気持ちよく使えてほしい面は、裁定ページと、1 日分を見渡して書き込む日次の面。

## Product Purpose

個人の暮らしと仕事の作業を、迷わず・速く・間違えずに進めるための Web の面(裁定フォーム・日次の面・学習と演習・ダッシュボード・読み物)が、
それぞれの目的に合った見た目と作りで、本人が実際に触って「期待どおり」と言える状態になること。面が共通のテーマを持つ必要はない(ADR-0000)。

この文書は、出発点(`config/web/` の `variables.css`・`components.css`・見本ページ)の製品文脈である。各面は、自分の `PRODUCT.md` と `DESIGN.md` を持ち、この文書を継がない。

## Operating Context

- 面はそれぞれ別のリポジトリで作られ、別の生成器で出力される。見た目は面ごとに決める。共有するのは、床(`page-types.toml` の要件と `behavior.js`)と、出発点の複写(区間の pin。使うかは面が決める)だけ。
- 配信は GitHub Pages・Cloudflare Workers のサイト・claude.ai の Artifact など複数。Artifact は、ホストが `data-theme` を付けることがある。
- 明暗は OS の設定に従う(切り替えの UI を持たない)。
- 順次の裁定や質問に答える面は、1 件ずつ進む構造(ステップ型)が既定(ADR-1711)。

## Capabilities and Constraints

- 出発点は、デジタル庁デザインシステム(DADS)を土台にした値(ADR-1677)。面は、これを採ってよく、採らなくてよい。共通のテーマは持たない(ADR-0000)。
- 共通に残すのは次の 4 つ。(1) 工程: 課題の性質 → 構造 → 練習用画面 → 面ごとに世界を選ぶ → Before と After を本人が判定する。(2) 床: コントラスト・押す領域・横スクロール・Space で押せる・構造の宣言(`page-types.toml`)と、保存・キー・読み込み中の振る舞い(`behavior.js`)。(3) 状態の色(成功・誤り・注意)の意味。色だけで状態を伝えない。(4) 通信の床: 第三者の配信元から書体・スタイル・スクリプトを読み込まない。
- WCAG 2.2 AA を満たす(文字 4.5:1、図形 3:1、押す領域 24×24 CSS px 以上)。
- 書体の選択は面ごと。自前のサイトから配信する Web フォントは使ってよい。第三者の配信元(Google Fonts など)からは読み込まない。
- 本人以外が使う面は、実利用者を確かめられないので、審査と機械検査にとどめる。

## Brand Commitments

- 避けたい見た目(本人が明示。2026-11-26): 事務的で味気ない / AI が作った感じ。(同日に挙げた「面ごとに別物に見える」は、共通のテーマをやめた 2026-11-27 に外した。)
- 固有の名前・ロゴ・声の規定は無い。デジタル庁のロゴ・キーカラーの規定は使わない(DADS の利用条件)。

## Evidence on Hand

- 本人が良い事例に挙げた実物: 練習問題のページ、裁定ページ、状況を見るダッシュボード(`docs/adr/1677-web-design-baseline.md`)。
- 現行の出発点: `config/web/variables.css`・`components.css`・`specimen.html`。値は DADS 由来の中立なもので、「どの見た目を目指すか」は面ごとに決める。
- 実物の画面の写真・利用者の声・計測値は、この文書には無い(作り話を足さない)。

## Product Principles

1. 操作が先、見た目は後。迷わず・速く・間違えずに進められることを、飾りより優先する。
2. 面の見た目は、その面の目的から決める。共通にするのは、利用者を守る床と、状態の色の意味だけ。
3. 状態は、色と言葉の両方で、その場で読める。
4. スマートフォンの片手と、PC のキーボードの両方で、同じ速さで使える。
5. 外へ要求を飛ばさない。表示のたびに第三者へ通信する部品を持たない。

## Accessibility & Inclusion

WCAG 2.2 AA。`prefers-reduced-motion` で動きを止める。フォーカスの見える形を持つ。文字を拡大できる(viewport で拡大を禁じない)。
