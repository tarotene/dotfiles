# 事例集

## 6件の関連Issueのうち、確定後に本文が更新されたのは1件だけだった

複数リポジトリに渡る設計変更(新しい通信経路を追加する提案)で、方式の天秤付けが1つの親Issueのコメント上で何度か更新され、最終的に確定した。しかし:

- 提案先リポジトリのIssue本文には「合意前の設計提案です」という警告バナーが残ったまま
- ペイロードの項目数・バイト配置・符号規約が、確定前の値のまま本文に残っていた
- 暫定的なコード番号(実は既存の別用途と衝突していて1回付け替えられていた)が、複数の関連Issue本文に散らばったまま残っていた
- 3つの子Issue(各対象への設計文書波及)にも同じ古い数値がそのままコピーされていた

親Issueのコメントには最終確定のログこそあったが、関連6件のIssue本文のうち1件を除く5件は古いまま放置されていた。

**教訓**: 天秤付けの過程をコメントに書くことと、確定後に本文を直すことは別の作業であり、後者を明示的にタスク化しないと素通りする。特に「暫定的な値」は、後から不要と判明した論点(この事例では「暫定コードの採番方法自体が、この提案の関心事ではなく別プロセスに委ねるべきだった」という気付き)を含めて、本文からきれいに落とす必要がある。議論の過程を全部本文に残すと、後から読む人に「まだ未確定なのか」という誤解を与える。
