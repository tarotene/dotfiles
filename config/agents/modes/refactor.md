# refactor モード

このセッションは `CLAUDE_MODE=refactor` で起動された。決定の記録に縛られずに整理するためのモードで、次のとおり動く。

- 決定の記録(ADR・設計文書。`docs/adr/`・`docs/agents/` など)は、読めず、書けない。読もうとして拒否されたときは、別の経路
  (シェルの `cat` や別のパス)で回避しない。記録の内容は、このセッションでは知らないものとして進める。
- 拘束するのは、落ちる検査(テスト・型・linter・CI)だけ。過去の決定を理由に、変更を止めない・小さくしない。
  変更が検査を落とすなら、検査を直すか、消す。検査を消す・変えるときは、何の検査をなぜ消したかを、PR 本文に残す。
- 共通規約のうち、決定の記録に関わる節(先行例の確認、方針の問いの前に既存の裁定を探すこと、決定成果物を執行点と同じ PR に出すこと、
  技術・仕組みの選択の 3 軸、道具を新設する前に既存手段を問うこと、Plan mode での先行例の書式)は、このセッションでは読み込まれていない。
  文脈に無い節は、思い出して適用しない。計画の書式の検査(先行例との対比・要求インベントリ)と、新しい道具の事前登録の検査は、止めてある。
  依頼の項目を黙って落とさない規範(要求インベントリの手順)は残っている。
- 安全に関わる規約は、これまでどおり有効: 外部への送信は下書き止まり、機体の契約の外にある非公開リポジトリは読まない、
  本物の checkout は変更せず worktree で作業する、コード変更は PR の作成までを完了とする。
- PR は `--draft` で作る。本文に `## 触れた決定` の節を置く。節は、PR を作る前に
  `decision-colocation-touched --base origin/<既定のブランチ>` を実行して、出力をそのまま貼る(変更前の ADR の執行点のうち、
  このセッションで変わった・消えたものと、消した・変えた検査が、機械的に出る)。検査を消す・変えた理由は、その下に 1 行ずつ足す。
  この一覧をもとに、通常のセッションで、覆す決定ごとに新しい ADR を同じブランチへ足す(記録の更新は、このセッションでは行わない)。
